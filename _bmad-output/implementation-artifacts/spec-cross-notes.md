# Cross-spec notes (specs-only pass, 2026-10-08)

Things found while planning later specs that affect earlier, not-yet-built specs. Resolve before or while implementing the named story.

- **spec-1-8 (fixed in spec):** chocolate voice lines exceeded 8 words because `voiceWords` splits "sô-cô-la" into 3 words. The 1.8 table now lists shorter chocolate lines.
- **spec-1-10 vs spec-2-1:** after 2.1, the level persists through `ProgressStore.getDifficulty/setDifficulty`; spec-1-10's "Session level" row (level back to 0 after reload) and its dev instruction to set `SessionStore.levels` by hand become outdated. 2.1 removes `SessionStore.levels/levelFor/recordRound`.
- **spec-1-6 lint:** spec-1-6 plans a pointer ban via `no-restricted-syntax` across `src/`. In ESLint flat config a second `no-restricted-syntax` block overrides the scenes/games one. When building 1.6, merge the selectors into the existing block (or use `no-restricted-globals`/`no-restricted-properties`, as spec-2-1 does).
- **Build order:** every spec edits files planned (not built) by earlier specs — implement strictly in story order.
- **spec-2-1 / spec-2-2 vs spec-2-3:** 2.3 moves Map's direct `ProgressStore.setDifficulty` call (spec-2-1) into `core/post-round-chain` (still synchronous on receipt), and extends 2.2's `syncDecorations` with a `hold` set so the wake after a round does not draw the new item (or drop the replaced one) before the fly-in. 2.3 also adds a `toWorld` option to `createTapRouter` (spec-1-5/1-6) so taps during the camera pull-back hit what is on screen.
- **spec-2-4 vs Epics 3/4 (forward note):** the overlay works for any new game through the generic `vo.shell.play-again-ask` line and the station-frame icon fallback. To get the AC-quality version, a game story adds `vo.shell.play-again-ask.<gameId>` ("Chơi nữa với bạn <nhân vật> nhé?") and a `content/play-again.ts › PLAY_AGAIN_ICONS` entry (model + creature colour), then re-renders `atlas.map` (`icon/<gameId>/00`). 2.4 also extends spec-1-7 (`KartTrip.replay`, `enter.via`, `enterStation` `zoomMs`) and spec-1-3's AudioDirector (`setPrompt(ids)`, `clearPrompt`, `stop(token)`).
- **spec-2-5 vs spec-1-7/1-8/1-10 (contract change):** 2.5 replaces the subclass `snapshot(): Snapshot` of spec-1-7 with `protected abstract progress(): { questionIndex, partial }`. `MiniGameBase.snapshot()` composes the envelope through `core/snapshot.ts › makeSnapshot`, adding `v`, `level`, `seed` and an optional base-owned `tally` (closed-question `RoundTally.state()`, so `nextLevel` stays fair across a resume). `Snapshot` becomes `Snapshot<G>` with a typed `partial` from `content/types.ts › SnapshotPartials`. spec-2-3's "round:abandon: no resume change" is superseded: Map now calls `SessionStore.setResume` on receipt.
- **spec-2-5 vs Epics 3/4 (forward note, the "lượt dở" stories 3.2, 3.4, 3.6, 4.2, 4.4, 4.6):** every game's `partial` is already declared in `SnapshotPartials` (pizza `{ placed: number[]; baked }`, dino-puzzle `{ placed: string[] }`, shadow-match and fishing `{}`, race `{ traceIndex }`, touch-talk `{ sceneId; touchedIds }`). If a story needs a different shape, edit only that entry. Each game:
  - implements `progress()` from its pure round model;
  - reads `this.resumeAt` (already envelope-checked by `readResume`) in `build()` and validates `partial` in a pure `resumeQuestion(index, partial)`. On failure it warns once and begins that question clean; an out-of-range index warns and starts from question 0;
  - begins the resumed question through `hint.beginQuestion` (level 0, prompt re-read).
  The ACs' literal `snapshot = { v, level, seed, questionIndex, partial }` should be asserted on the model's `progress()` or with `toMatchObject`, because the base adds `tally`. Games never touch `SessionStore`. Map's resume start, the mark and consume-on-start work with no per-game code.
- **spec-2-5 vs Epic 4 touch-talk:** Map always passes `level: 0` for `touch-talk`. Keep `touchedIds` as the distinct ids since the last `reward:earned`, so a resumed scene continues the ~8-touch count (Story 4.6: 5 restored + 3 new → `reward:earned`). Its `questionIndex` should be the current scene's index; `sceneId` is the check.
- **spec-4-1 vs spec-1-8/1-9/2-4 and Epic 3 (shared surfaces):** 4.1 widens `HintStep` (`correct`/`distractors` → structural `HintItem { object?, onLiftChange? }`; `path` may be a getter resolved per hand demo), makes spec-2-4's `PLAY_AGAIN_ICONS[*].creature` optional (absent → source colours; used by the race kart icon), and adds `tools/layout/hud-keep-out.ts › hudKeepOutRects()` (120×120 Home/Speaker zones over both supported aspects, from spec-1-6's `hudLayout`). Epic 3 (3.3/3.5 keep-out rule, tap-game hint items) is built first: if it introduces an equivalent helper or `HintStep` widening, 4.1 reuses it instead. 4.3/4.5 should reuse `hudKeepOutRects`. 4.1 also generalises spec-1-7's `core/road.ts` to any polyline if it was built map-bound.
- **spec-3-1 vs core (shared surfaces, built before Epic 4):** 3.1 introduces the structural `HintItem { object?, onLiftChange? }` for `HintStep.correct`/`distractors` (same shape spec-4-1 plans — 4.1 reuses it), `tools/layout/hud-keep-out.ts › hudKeepOutRects()` (4.1/4.3/4.5 and 3.3/3.5 reuse it), a new Bus event `speech:line { token, index, id }` emitted by AudioDirector at each line start (for count-in-time bounces), `createDropTarget` circle `pad` (hit r = pad + r × snapScale), `VoiceLine.review?` with a `REVIEW_WORDS` rule (unapproved lines containing "pizza"/"xúc xích" must carry `review`), and a `BANNED_PHRASES` rule ("sai", "không đúng", praise words) in `content/validate.ts`.
